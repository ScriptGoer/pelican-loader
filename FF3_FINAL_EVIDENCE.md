# FF3 V26.21: final-check evidence

An automatic pass can qualify during planning and fail a later fresh release check. The old recorder could attach that later rejection reason to the earlier candidate's positive clearances. A failed native calculation could similarly inherit an earlier valid tuple. This made some blocked records contradictory without proving that either the throw or rejection was correct in-game.

Final preparation now carries a separate rejection receipt. `EvidenceStage` distinguishes a planned candidate, winner-solve failure, final context check, final native solve, ungraded native tuple and final current coverage. A failed current-coverage check retains the actual newly graded trajectory. If no valid final tuple exists, top-level valid-trajectory margin/lane/time remain absent. Native aimpoint residual/tolerance and rejected coordinates are saved separately under `SolverFailure` when available. An old candidate is never substituted as the failed final calculation.

Blocked records also include up to nine `ModeTrials` entries for that receiver, from existing cached native returns and the last planning-pass failure reasons. Return/failure ages are explicit. These entries do not claim fresh coverage grades, and unobserved alternatives are not invented as safe or unsafe. The global Bullet-control trace is labelled as global rather than proof of a particular receiver's attempt.

No extra native solve, roster scan, network worker, listener or HUD row is added. Anonymous history actors, the same record schema and 100-record/80,000-byte limits remain. Extra diagnostics can shorten the retained window within that fixed budget; uploads are not exhaustive logs of every player or opportunity. Credentials, raw private history, video, chat and paid source are not distributed.

This release changes diagnosis, not throwing permissions. Receiver scheduling, safe/covered selection, strict Bullet coverage, holding-high restrictions, comfort timing, leads, risk/filter choices, goal/LOS checks, jump timing, ownership, one-request/ambiguity handling and cleanup are unchanged. Both ordinary and competitive loaders pin `ff3-v26.21`; X reloads normally. V26.20 remains at its immutable tag. Other game and companion source bytes remain unchanged.

All 58 standalone Lua contract suites pass. The new 66 checks reproduce the old positive-clearance/final-rejection contradiction, test fresh/failing native receipts, bounded aged mode diagnostics and cleanup in CASUAL/LEAGUE. Differential safe-release cases preserve packet, target, release time and native calculation count. Native Luau compilation and bundle smoke checks pass. These tests do not establish real catchability, correct live interception boundaries, paid-build compatibility or iPhone performance.
