## Native angle behavior

The inspected native source uses power 95 and a low ballistic branch for Fit/Bullet. Dime/Jump can calculate power from the same configured angle on successive throws, explaining the repeated angle when the configuration stays fixed. ARC AUTO changes Dime/Jump requests according to the current lane, without changing per-mode catch leads. The opt-in MagDime trial uses the same angle calculation with its separate trusted-only Y increment; its catch calibration remains missing.

For each eligible Dime/Jump candidate, a bounded four-iteration estimate uses current QB/receiver pose, observed receiver motion, ping, configured X/Y lead, existing field clamps and the configured power ceiling (up to 95). It begins with the low ballistic branch at that ceiling and retains the existing gentle flight-time policy when enabled. Receiver lead is recalculated at the estimated flight time.

A defender is considered for extra loft only if its projected horizontal position lies between QB and catch point and inside the existing lateral body/turn envelope. Required vertical clearance reuses the existing defender jump-reach estimate and lane safety allowance. For a defender at horizontal fraction `f`, the estimator uses the ballistic identity `height(f) = originY + f*heightDifference + 0.5*g*T^2*f*(1-f)` to find the additional flight time needed to clear that modeled height. All defenders within an iteration use the same probe flight time. The maximum required time determines the next angle. An open outside receiver can still receive a low angle; an underneath defender on an inside route can still justify loft or refusal. Receiver labels and inside/outside position alone do not select arcs.

This is a placement proposal, not a release authority. The actual native solver is called with the derived degree value in a protected Angle scope, even when the user's global input mode is Power. ManualType/Angle and other owned settings are restored synchronously before returning to input. Power-mode configuration remains intact outside the calculation. Returned power must remain within the configured cap plus the source's one-unit rounding allowance. The actual angle is recorded separately: live evidence has input 45 producing roughly 40–41 degrees. Native final correction is allowed, with the returned trajectory fully rechecked. An input/release equality gate would reject supported behavior. These are control/trajectory checks, not calibrated catch mechanics. The solver's actual origin, velocity, flight time and arrival go through all existing path, receiver-reach, coverage, plan, comfort and final freshness checks.

Fit/Bullet keep their native low-branch calculation and power policy. Safe Bullet/soft Bullet options remain available. Fit still needs its established timing rescue; this update does not force Fit merely because a receiver is inside. A safety over the top still blocks an unsafe elevated pass. A nearby defender, high requested angle or apparently open receiver never bypasses those checks. Infeasible/stale estimates or an excessive native power result reject the affected Dime/Jump candidate instead of silently substituting 45 degrees. Other modes and manual locks retain their existing behavior.

The estimator reuses the existing decision roster and recently returned native launch origins. Within one physics frame, unchanged mode/lead/poses/configuration reuse the same estimate. There are no additional native solves, new world scans, extra release waits, new background workers or movement/catch hooks. The existing six-planning-call/time budget and eight-native-calls-per-frame cap remain. Stop clears angle scene/cache references; cleanup/ownership conflicts retain stop-and-preserve behavior.

The inherited jump reach, turn envelope, pursuit bounds and model speed-to-server conversion are still approximate. A useful requested loft can be rejected by the more conservative full pursuit model. Small launch-origin or SmartPass differences remain possible, and the final native path—not the estimated path—must pass. Native settings/solver compatibility, actual catch success and mobile overhead require live validation.

## End zone and goal LOS

The existing code already removes the six-yard receiver minimum when goal-to-go HUD text is recognized. The new exception also accepts moving eligible receivers in the **attacking end zone** when an ordinary down label is present, provided the blue/yellow LOS is independently valid. Both current receiver position and actual native arrival must independently pass depth/field checks. An end-zone arrival is also a DEEP-plan exception, so a short touchdown target does not need 20 yards of depth. This reuses the existing validated field frame, goal-stripe coordinates at local +/-150 and existing +/-180 bounds. It does not infer attack direction from camera, receiver motion or an unverified game ID.

An LOS coinciding with the goal stripe no longer produces a zero-direction error. Verified goal direction continues into the end zone; a goal LOS beyond the target stripe is rejected instead of reversing toward midfield. A previous paired direction is only reused with the same team and possession epoch. A new play cannot inherit an opposing goal direction solely because its LOS occupies the same position.

Near the goal line, the center-only QB threshold can reject a root that still physically overlaps LOS. Goal-to-go now uses the root's measured projected horizontal half-extent, with the existing 0.5-stud minimum tolerance. A fully crossed root remains blocked. Ordinary downs retain the original 0.5-stud threshold. This is an explicit geometric overlap policy, **not a verified statement of the server's legal-pass boundary**. Reports retain QB center depth and allowed overlap for follow-up. The exact cause of the user's intermittent live `QB_PAST_LOS` message is not established without its report.

End-zone eligibility does not waive AFK/movement evidence, team/filter/blacklist, field, catch-point, coverage, LOS validation or a fully crossed QB check. The own end zone and out-of-bounds space do not qualify. Goal play is not disabled and LOS is not ignored.
